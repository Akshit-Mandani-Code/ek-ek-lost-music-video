# AI Prompt Architecture — Self-Contained by Design

The repository's prompts must work without attaching any existing image. A future AI must be able to start with text only, generate its own internal references, and then create the shots.

## 1. Written visual canon
The character bibles, visual style bible, environment bible and prop continuity bible are the canonical source. Prompts must repeat the relevant identity and continuity details rather than relying on undocumented visual memory.

## 2. Character bootstrap
Before creating story shots, generate:
- A protagonist character sheet using the complete written protagonist bible.
- A mother character sheet using the complete written mother bible.
- Any required age/timeline variations (adult son and newborn memory; mother in present and earlier memory).
- Consistent wardrobe views and neutral expression/pose variations where useful.

Select one internally consistent design per character for that recreation. Reuse the generated sheet as an optional internal image reference when the platform supports it. If it does not, repeat the full written identity description in every prompt and use stable model/settings/seeds where available.

## 3. Environment and prop bootstrap
Generate text-led reference views for recurring locations and important props using the repository's descriptions. Keep the same architecture, room layout, materials, furniture, object design and wear across shots. These references are generated by the future AI; they are not required external inputs.

## 4. Still-image prompt
Every shot prompt must specify:
- Complete relevant character description and wardrobe state.
- Scene/location, time and physical environment.
- Character position, pose, expression and exact captured action.
- Camera framing, angle, composition, lens/look and focus.
- Lighting, color palette, atmosphere and texture.
- Props and their placement.
- Narrative emotion and continuity constraints.
- Negative constraints preventing common generation failures.

## 5. Animation prompt
Specify separately:
- Camera movement or explicitly locked camera.
- Subject movement, small and physically plausible.
- Environmental motion (water, fabric, background extras, etc.).
- Duration and motion pacing.
- What must remain unchanged: identity, clothing, composition, geometry, lighting and scene layout.
- What must not happen: morphing, facial drift, extra limbs, camera warping, sudden cuts unless requested.

## 6. First-frame / last-frame workflow
Design both stills with matching camera, lens feel, framing, subject scale and lighting. Change only the intended story state. Describe the transition path between endpoints. Do not rely on external images to define either endpoint.

## 7. Optional current-production references
Our current approved CH3 portrait and any images generated during this production may be attached as optional aids. Every prompt must remain fully understandable and usable if those images are absent. Never write “exact same person as attached image” as the only identity instruction.

## 8. Master prompt policy
Keep a model-agnostic master prompt as the source of truth. Store model-specific adaptations separately; never overwrite the master. Record tool, model, settings, aspect ratio, seed (if available), optional references and output filename for each current generation.

## 9. Prompt write-through policy
Every production-ready prompt written in chat must also be saved in the relevant repository folder during the same working session. Preserve exact text and assign a prompt ID/version. Keep superseded versions when they have been used.

## Production priority
Develop the self-contained character-generation prompts first. Then create the three key hoodie reference stills: bathroom water-splash, hooded faceless protagonist, and mother-lap ending. Do not animate before stills pass continuity review.
